# Expiry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the complete Day 14 Expiry application with browser encryption, Supabase authentication and persistence, atomic one-view reveal, private history, database-backed rate limits, and a polished responsive interface.

**Architecture:** A Vite React SPA selects a local demo repository when Supabase public configuration is absent and otherwise uses Supabase Auth plus Vercel API handlers. Privileged handlers use a server-only Supabase secret key; PostgreSQL functions provide atomic reveal and rate-limit operations while RLS isolates each creator's history.

**Tech Stack:** React 19, TypeScript 6, Vite 8, Supabase JS 2, Web Crypto API, Vitest, Testing Library, Playwright, Vercel Functions, PostgreSQL/PLpgSQL, CSS.

**Spec:** `docs/superpowers/specs/2026-09-14-expiry-design.md`

## Global Constraints

- Recreate `day-14-expiry`; do not modify another day's application.
- Plaintext and URL-fragment encryption keys must never be included in database or API persistence payloads.
- Creator text is limited to 10,000 characters and titles to 120 characters.
- After-opening secrets have at most one successful reveal; time-based secrets remain available until the server-side deadline.
- History persists after ciphertext is cleared and is accessible only to its owner.
- Recipients never authenticate.
- Copy prevention is presented only as deterrence.
- Empty Supabase public configuration activates an explicitly labeled, same-browser demo mode.
- Use no gradients, glassmorphism, dashboard grid, sidebar, illustration, analytics, or unnecessary UI library.
- Use `.env` only for local placeholders and `.env.example` for documented variable names; never commit real credentials.
- Every behavior task follows red-green-refactor and ends with its focused tests passing.
