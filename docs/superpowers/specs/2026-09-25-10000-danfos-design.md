# 10,000 Danfos Design

## Goal

Build Day 26 as a technical game: a full-canvas, Lagos-inspired traffic simulation that is immediately playful but exposes real engineering mechanics beneath the spectacle.

## Experience

- Open on a cinematic poster-like landing view with the city simulation already establishing atmosphere.
- Calibrate to the visitor's device before entering the main city.
- Let the visitor scale from 500 to 10,000 visible Danfos, disturb traffic with pointer forces, place roadblocks, inspect vehicles, and compare spatial-search engines.
- Surface real counters for frame time, simulation time, candidate checks, neighbours, and occupied cells.
- Keep deep controls in restrained side panels so the simulation remains the main event.
- Support keyboard controls, replay, a guided tour, audio, photo mode, result-card export, responsive layouts, and reduced visual quality where needed.

## Architecture

React owns interface state through Zustand, never per-agent positions. A simulation runtime owns typed arrays, routing tables, neighbour structures, and metrics; it runs through a module worker and sends transferable render snapshots to the main thread. React Three Fiber renders the road graph and all Danfos with instancing, while overlays reveal the grid, neighbours, density, flow, traffic lights, and pointer influence.

Grid, naive, and quadtree modes share the same simulation state so their results and costs can be compared. Floyd-Warshall routing handles roadblocks and rerouting. A small WebGPU probe is explicitly experimental and falls back cleanly when unavailable.

## Visual System

Visual thesis: a nocturnal Lagos traffic laboratory—charcoal city, warm off-white typography, and one Danfo-yellow accent, animated by dense vehicle movement rather than decorative chrome.

The landing screen behaves like a poster. The city screen uses sparse HUD labels, hairline dividers, and translucent utility panels rather than a dashboard-card mosaic. Typography is compact, uppercase, and technical. Motion comes from traffic, camera travel, panel transitions, calibration progress, and clear hover/focus feedback.

## Reliability

- Seeded state must be deterministic.
- Grid neighbour results must match brute force on deterministic fixtures.
- Pathfinding must find routes and reroute around blocked edges.
- Naive search is capped by measured device safety limits.
- Build, lint, unit tests, and responsive browser checks must pass before dashboard integration.
